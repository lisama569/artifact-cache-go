# artifact-cache-go

基于本地文件系统的构建产物缓存，提供稳定缓存键派生、并发构建合并、
原子写入与完整性校验、条目有效期（TTL）、按需巡检/自愈、
容量回收与版本兼容。仅依赖 Go 标准库，
不访问网络、外部服务或真实凭据。

## 缓存键派生规则

`cache.DeriveKey(BuildInput)` 对声明式构建输入做规范化后计算 SHA-256：

- **文件内容**：按路径字典序排序，逐一写入 `file <path> <len>\n<content>`；
- **工具链标识**：写入 `toolchain <id>\n`，为空则报错；
- **构建参数**：按给定顺序写入 `arg <value>\n`（参数顺序有语义，不排序）；
- **受管环境变量**：按变量名排序写入 `env <name>=<value>\n`，
  只有显式列入 `BuildInput.Env` 的变量参与派生。

语义等价的输入（如 map 插入顺序不同）得到相同键；内容、工具链、
参数或受管环境变量任一变化都会改变键。

每次访问返回 `Result{Hit, Reason, Built}`，原因可区分且可解释：

| Reason | 含义 |
| --- | --- |
| `hit` | 直接命中 |
| `miss: not found` | 无此条目，由本请求构建 |
| `miss: expired entry` | 条目已超过有效期，即使内容完好也不复用，重建 |
| `miss: corrupted entry: …` | 条目截断/校验和不符，按未命中处理并重建 |
| `…; shared build result` | 合并到并发构建，复用其结果 |

## 有效期（TTL）

- **实例默认**：`Open(dir, maxBytes, cache.WithMaxAge(d))` 设置默认最大
  存活时长；`d <= 0`（或不设置）表示条目默认永不过期。
- **单次覆盖**：`GetOrBuildWithTTL(ctx, key, ttl, build)` 按次指定：
  `ttl > 0` 使用该有效期；`ttl = 0` 回落到实例默认；`ttl < 0` 本次
  写入永不过期。`GetOrBuild` 等价于 `ttl = 0`。
- **判定**：过期时间随条目一起持久化（v3 格式头部），判定使用
  `now() >= expiresAt`；到期条目即使内容完好也不得复用，按未命中重建，
  并计入 `Stats.Expired`。
- **可控时钟**：有效期判定不依赖真实时间流逝。`WithClock(fn)` 注入
  时间源，测试中用手动时钟把逻辑时间往前推即可确定性地触发过期，
  无需 `time.Sleep`。
- **过期条目的清除**发生在三个时机：访问时（惰性）、`Open` 扫描时、
  `Sweep` 巡检时，均计数。

## 巡检与自愈（Sweep）

`Sweep()` 按需触发，扫描整个缓存目录并自愈，返回 `SweepReport`：

| 字段 | 含义 |
| --- | --- |
| `Expired` | 因过期被移除的条目数 |
| `Corrupted` | 损坏/校验失败被移除的条目数 |
| `Orphaned` | 磁盘有、索引没有的孤儿文件（已清除） |
| `Missing` | 索引有、磁盘缺失而被剔除的条目数 |
| `Repaired` | 索引记录与磁盘不符、已按磁盘修正的条目数 |
| `Adopted` | 巡检期间已落盘、尚未入索引的并发构建产物（已纳入索引） |
| `Entries`/`Bytes` | 巡检后的条目数与占用，**与磁盘实际占用完全一致** |

一致性保证：

- 巡检全程持有缓存互斥锁，与并发读写、淘汰安全交错；条目移除
  （`removeLocked`）幂等，多个请求同时撞上同一个坏条目不会重复扣减
  占用统计。
- 构建的产物落盘（临时文件 rename 为正式文件）不依赖缓存锁，因此
  巡检扫描期间磁盘上可能多出尚未入索引的完整产物。巡检在扫描中途
  主动**认领**这些 inflight 产物：按磁盘内容校验后直接纳入索引
  （`Adopted` 计数），并钉住（refs>0）防止被巡检末尾的淘汰清掉；
  构建随后入索引时按同键替换，幂等、不重复计数。因此**巡检返回的
  那一刻**，报告中的条目数与字节数即与目录真实占用完全一致，
  无需等待并发构建全部结束。
- 正在进行中的并发构建（inflight）写入的文件不会被误判为孤儿；
  残留临时文件仅在没有进行中构建时清理；仍在写入中的临时文件
  字节计入报告 `Bytes`（它们真实占用磁盘），但不计入条目数。
- 无论巡检与读写如何交错，结束后 `SweepReport.Bytes`、`Stats.Bytes`
  与目录实际占用三者一致；后续继续写入时，LRU 淘汰仍能把真实占用
  压回上限以内（巡检结束时也会补做一次淘汰）。

## 并发与完整性保证

- **单飞合并**：同一键的并发 `GetOrBuild` 只执行一次实际构建，
  其余请求阻塞等待并复用结果；`Stats.Builds` 记录真实构建次数。
- **失败不缓存**：构建失败不写入任何条目，所有等待者收到相同错误，
  后续请求可正常重试。
- **原子写入**：条目先写同目录临时文件、fsync 后 rename，
  读者只能看到完整旧条目或完整新条目，绝不看到部分写入。
- **完整性校验**：条目格式为
  `magic + version + 过期时间 + 长度 + SHA-256 + 负载`，
  读取时校验长度与校验和；截断或篡改的条目按未命中处理并移除重建。

## 回收策略

- 容量上限由 `Open(dir, maxBytes)` 指定；超限后按 **LRU**
  （最久未使用优先）淘汰，直至占用不超过上限。
- 正在被读取的条目（引用计数 > 0）被钉住，不得淘汰；
  引用释放后补做回收。
- 统计口径一致：`Stats.Bytes` 等于索引中各条目大小之和，
  与磁盘实际占用一致（测试中以目录扫描校验）。

## 版本兼容

- **v3（当前）**：`magic + version=3 + 过期时间(8) + 长度(8) +
  SHA-256 + 负载`，过期时间随条目持久化（0 = 永不过期）。
- **v2（旧版）**：无过期时间的带校验和格式。Open 时校验通过即无损
  迁移到 v3（`Stats.Migrated` 计数）并继续可用；校验失败则拒绝。
- **v1（旧版）**：`magic + version=1 + 裸负载`，Open 时无损迁移到 v3。
- **迁移规则（确定、可解释）**：旧格式不含有效期信息，迁移后一律
  视为永不过期；用同一旧目录启动的结果总是确定的。
- **其他**（无 magic、未知/更高版本、损坏条目）：明确拒绝并移除
  （`Stats.Rejected` 计数），绝不静默误用为当前版本。

## 本地验证

```sh
go build ./...
go test ./...          # 全部单测
go test -race ./...    # 并发正确性
go test -count=3 ./... # 可重复执行
go test -v ./...       # 查看缓存键、命中/未命中原因、构建次数与占用统计日志
```

测试覆盖：键派生稳定性与敏感性、并发同键构建（实际构建仅一次）、
构建失败不缓存、截断/篡改条目按未命中重建、读取期间回收且占用不超上限、
条目过期后不再复用（手动时钟）、单次 TTL 覆盖、Open 时过期条目清理、
多请求同时撞上坏条目时占用统计一致、巡检分类清理与计数、
巡检与并发读写交错后占用与磁盘一致、巡检后超限淘汰仍生效、
v1/v2 旧格式迁移与拒绝、统计口径与磁盘占用一致性。

### 复现"巡检与并发构建落盘交错"

`TestSweepAdoptsInflightLandedBuilds` 稳定复现该交错时序：两个并发构建
先停在构建过程中，巡检开始扫描；扫描中途（测试钩子）放行构建，让产物在
巡检返回前 rename 落盘；随后断言巡检返回瞬间报告的条目数/字节数与目录
真实占用一致、再读一次 `Stats` 三者一致，并覆盖巡检后继续写入触发淘汰
压回上限、失败构建重试、二次巡检计数稳定。本地验证：

```sh
go test -run TestSweepAdoptsInflightLandedBuilds ./cache/ -v
go test -race -count=5 -run 'Sweep|Concurrent|Eviction' ./cache/
```
