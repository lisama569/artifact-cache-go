# artifact-cache-go

基于本地文件系统的构建产物缓存，提供稳定缓存键派生、并发构建合并、
原子写入与完整性校验、条目有效期（TTL）、按需巡检/自愈、容量回收
与版本兼容。仅依赖 Go 标准库，不访问网络、外部服务或真实凭据。

## 缓存键派生规则

`cache.DeriveKey(BuildInput)` 对声明式构建输入做规范化后计算 SHA-256：

- **文件内容**：按路径字典序排序，逐一写入 `file <path> <len>\n<content>`；
- **工具链标识**：写入 `toolchain <id>\n`，为空则报错；
- **构建参数**：按给定顺序写入 `arg <value>\n`（参数顺序有语义，不排序）；
- **受管环境变量**：按变量名排序写入 `env <name>=<value>\n`，
  只有显式列入 `BuildInput.Env` 的变量参与派生。

语义等价的输入（如 map 插入顺序不同）得到相同键；内容、工具链、
参数或受管环境变量任一变化都会改变键。

每次访问返回 `Result{Hit, Reason, Built}`，原因可区分且可解释：

| Reason | 含义 |
| --- | --- |
| `hit` | 直接命中 |
| `miss: not found` | 无此条目，由本请求构建 |
| `miss: expired` | 条目超过有效期，即使内容完好也不复用，重建 |
| `miss: corrupted entry: …` | 条目截断/校验和不符，按未命中处理并重建 |
| `…; shared build result` | 合并到并发构建，复用其结果 |

## 有效期（TTL）

- **实例默认值**：`OpenWithOptions(dir, maxBytes, OpenOptions{DefaultTTL: d})`
  为缓存实例配置默认最大存活时长；`d<=0` 表示默认永不过期。
  `Open(dir, maxBytes)` 等价于不配置默认 TTL。
- **单条覆盖**：`GetOrBuild(ctx, key, build, cache.WithTTL(d))` 为本次
  写入单独指定 TTL：`d>0` 覆盖实例默认；`d<=0` 表示该条目永不过期。
  未指定时使用实例默认值。
- **判定规则**：条目在 `写入时刻 + TTL` 及之后视为过期（`now >= created+TTL`）。
  过期条目即使内容完好也不复用，按未命中重建，`Result.Reason` 为
  `miss: expired`，与 `miss: not found`（不存在）、
  `miss: corrupted entry: …`（内容有问题）明确区分。
- **持久化**：创建时间与 TTL 随条目一起写入 v3 格式头部，
  重启后仍按持久化的时间判定。
- **可控时钟**：有效期判定通过 `OpenOptions.Clock` 注入时间来源，
  默认系统墙钟；测试用 `NewFakeClock(start)` 创建可控时钟，
  `Advance(d)` 把时间往前推，不依赖真实时间流逝，结果完全确定。

## 巡检与自愈（Sweep）

`c.Sweep()` 按需触发，扫描整个缓存目录并返回 `SweepReport`：

- 移除**已过期**条目（`Expired` 计数）；
- 移除**损坏**（截断/校验和不符）条目（`Corrupted` 计数）；
- 修正**索引与磁盘对不上**的条目：索引有磁盘无的删除索引、
  大小漂移的以磁盘真实大小对账（`Mismatched` 计数）；
- 删除索引没有的**残留文件**；内容完好且未过期的 v3 孤儿文件
  收养进索引（`Orphans` / `Adopted` 计数）；
- 最后按容量上限回收，报告 `Entries`/`Bytes`。

被清理的条目后续访问时按未命中重建（该重建的重建）。

**一致性保证**：所有索引变更、条目读取、rename 后的索引登记都在同一
互斥锁内完成；巡检持锁扫描、等待进行中的构建完成、并在结束前对账，
期间新构建被暂停。因此无论巡检与并发读写如何交错：

- 巡检结束时报告的条目数与占用**与磁盘真实占用完全一致**；
- 巡检之后继续写入，LRU 淘汰仍能把真实占用压回上限以内；
- 中途任意时刻满足结构不变量：索引条目必在盘上且大小一致，
  盘上最终文件必属于索引或进行中的构建，账面占用不超上限。

## 并发与完整性保证

- **单飞合并**：同一键的并发 `GetOrBuild` 只执行一次实际构建，
  其余请求阻塞等待并复用结果；`Stats.Builds` 记录真实构建次数。
- **失败不缓存**：构建失败不写入任何条目，所有等待者收到相同错误，
  后续请求可正常重试。
- **原子写入**：条目先写同目录临时文件、fsync 后 rename，
  读者只能看到完整旧条目或完整新条目，绝不看到部分写入。
- **完整性校验**：v3 条目格式为
  `magic + version + 长度 + SHA-256 + 创建时间 + TTL + 负载`，
  读取时校验长度与校验和；截断或篡改的条目按未命中处理并移除重建。

## 回收策略

- 容量上限由 `Open`/`OpenWithOptions` 的 `maxBytes` 指定；超限后按
  **LRU**（最久未使用优先）淘汰，直至占用不超过上限。
- 统计口径一致：`Stats.Bytes` 等于索引中各条目大小之和，
  与磁盘实际占用一致（测试中以目录扫描校验）。

## 版本兼容与升级规则

当前格式为 **v3**（带创建时间与 TTL）。用存量缓存目录启动时行为确定：

- **v3（当前）**：直接纳入索引。
- **v2（上一代）**：`magic + version=2 + 长度 + SHA-256 + 负载`。
  按确定规则升级为 v3：负载经长度与校验和校验后保留；
  **创建时间取文件 mtime**（旧格式不带时间，升级时刻即落盘时刻，
  结果确定且可解释）；**TTL 取实例默认值**（`DefaultTTL<=0` 则永久有效）。
  升级条数计入 `Stats.Migrated`。
- **v1（更早）**：`magic + version=1 + 裸负载`。升级规则同 v2
  （无校验和可验，全部字节即负载）。
- **其他**（无 magic、高于当前的版本、校验失败、截断损坏）：
  明确拒绝并从磁盘移除，计入 `Stats.Rejected`，**绝不静默当作
  新格式使用**；被拒绝条目后续访问按未命中重建。

升级是一次性且幂等的：同一目录再次打开时 `Migrated`/`Rejected` 均为 0，
升级后的条目继续可用。升级后已过期（按持久化时间与当前时钟判定）的
条目不会被复用，在访问时（懒过期）或巡检时移除并重建。

## 本地验证

```sh
go build ./...
go test ./...          # 全部单测
go test -race ./...    # 并发正确性
go test -count=3 ./... # 可重复执行
go test -v ./...       # 查看缓存键、命中/未命中原因、构建次数与占用统计日志
```

测试覆盖：键派生稳定性与敏感性、并发同键构建（实际构建仅一次）、
构建失败不缓存、截断/篡改条目按未命中重建、读取期间回收且占用不超上限、
条目过期后不再复用（含单条 TTL 覆盖与跨重启持久化）、
三类未命中原因区分、巡检清理过期/损坏/不符/孤儿条目且报告与磁盘一致、
巡检与并发读写交错时占用统计始终一致、巡检后超限淘汰仍然生效、
v1/v2 旧格式升级与不可识别条目拒绝、统计口径与磁盘占用一致性。
