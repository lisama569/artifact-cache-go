# artifact-cache-go

基于本地文件系统的构建产物缓存，提供稳定缓存键派生、并发构建合并、
原子写入与完整性校验、容量回收与版本兼容。仅依赖 Go 标准库，
不访问网络、外部服务或真实凭据。

## 缓存键派生规则

`cache.DeriveKey(BuildInput)` 对声明式构建输入做规范化后计算 SHA-256：

- **文件内容**：按路径字典序排序，逐一写入 `file <path> <len>\n<content>`；
- **工具链标识**：写入 `toolchain <id>\n`，为空则报错；
- **构建参数**：按给定顺序写入 `arg <value>\n`（参数顺序有语义，不排序）；
- **受管环境变量**：按变量名排序写入 `env <name>=<value>\n`，
  只有显式列入 `BuildInput.Env` 的变量参与派生。

语义等价的输入（如 map 插入顺序不同）得到相同键；内容、工具链、
参数或受管环境变量任一变化都会改变键。

每次访问返回 `Result{Hit, Reason, Built}`，原因可区分且可解释：

| Reason | 含义 |
| --- | --- |
| `hit` | 直接命中 |
| `miss: not found` | 无此条目，由本请求构建 |
| `miss: corrupted entry: …` | 条目截断/校验和不符，按未命中处理并重建 |
| `…; shared build result` | 合并到并发构建，复用其结果 |

## 并发与完整性保证

- **单飞合并**：同一键的并发 `GetOrBuild` 只执行一次实际构建，
  其余请求阻塞等待并复用结果；`Stats.Builds` 记录真实构建次数。
- **失败不缓存**：构建失败不写入任何条目，所有等待者收到相同错误，
  后续请求可正常重试。
- **原子写入**：条目先写同目录临时文件、fsync 后 rename，
  读者只能看到完整旧条目或完整新条目，绝不看到部分写入。
- **完整性校验**：条目格式为 `magic + version + 长度 + SHA-256 + 负载`，
  读取时校验长度与校验和；截断或篡改的条目按未命中处理并移除重建。

## 回收策略

- 容量上限由 `Open(dir, maxBytes)` 指定；超限后按 **LRU**
  （最久未使用优先）淘汰，直至占用不超过上限。
- 正在被读取的条目（引用计数 > 0）被钉住，不得淘汰；
  引用释放后补做回收。
- 统计口径一致：`Stats.Bytes` 等于索引中各条目大小之和，
  与磁盘实际占用一致（测试中以目录扫描校验）。

## 版本兼容

- **v2（当前）**：带长度与校验和的完整格式。
- **v1（旧版）**：`magic + version=1 + 裸负载`，Open 时无损迁移到 v2
  （`Stats.Migrated` 计数）。
- **其他**（无 magic、未知/更高版本、损坏条目）：明确拒绝并移除
  （`Stats.Rejected` 计数），绝不静默误用为当前版本。

## 本地验证

```sh
go build ./...
go test ./...          # 全部单测
go test -race ./...    # 并发正确性
go test -count=3 ./... # 可重复执行
go test -v ./...       # 查看缓存键、命中/未命中原因、构建次数与占用统计日志
```

测试覆盖：键派生稳定性与敏感性、并发同键构建（实际构建仅一次）、
构建失败不缓存、截断/篡改条目按未命中重建、读取期间回收且占用不超上限、
旧版本条目迁移与拒绝、统计口径与磁盘占用一致性。
